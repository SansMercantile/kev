# KEV internationalization (i18n)

`react-i18next` with 6 full UI languages: English (reference), isiZulu,
isiXhosa, Afrikaans, French, Spanish. The switcher in the site/platform nav
persists to `localStorage` (`kev_language`), honors `?lang=` (shared
constellation semantics: query override, then saved choice, then browser
language, then English), and sets `<html lang>` (+ `dir`, LTR today).

## The world model: 198 countries, every home language

Beyond the 6 UI bundles, `backend/core/world_languages.py` catalogues all
**198 globally recognized countries** (193 UN members + Vatican City,
Palestine, Taiwan, Kosovo, Cook Islands) with official + major local
languages (~96 registry languages with native names + RTL flags).

- `GET /xr/world/languages[?country=ZA][?q=swahili]` serves the catalog.
- The nav switcher's **198 🌍** browser: pick a country → UI jumps to the
  best bundled match when one exists; otherwise chrome stays in the UI
  language while **tutor answers follow the home language**
  (`kev_answer_language`, shown as an "answers:" chip, clearable).
- `?lang=sw` deep-links the same behavior.
- Every tutor endpoint accepts any catalog code/name/variant
  (`normalize_language`) and instructs Bedrock to answer in it; responses
  echo the resolved `language`. RTL answers render with `dir="auto"`.

## Shared constellation tech (fully integrated)

- `shared_resources.i18n.python.negotiator` — Accept-Language + `?lang`
  negotiation reused for API message language (quota errors).
- `shared_resources.i18n.python.context.I18nContext` — bundle lookup with
  English fallback, pointed at KEV's `backend/i18n/locales` bundles
  (billing messages in all 6 UI languages).
- Both degrade to English when the shared package is unavailable.
- NOT integrated: `ai_infrastructure/src/ising_decoder.py` — despite the
  name it is a quantum/Ising optimization decoder (aviation, climate, space
  domains), unrelated to human languages.

## What's translated (UI chrome)

- Site + platform shell: nav, auth buttons, sign-in gates, footers, menus.
- Immersive Lab + Human Atlas: headers, subject/system names, search,
  isolate/explode controls, detail panel, level banner, tutor panel.
- Tutor Q&A everywhere (TutorAskPanel): prompts, buttons, level chip.
- Curriculum page, Pricing page, cross-surface link labels.
- XR Academy shell: view tabs, toolbar, lab tabs, mobile drawer, campus
  overlay, map modal, dashboard tabs + panels.
- AI tutor answers follow the UI language: every tutor call sends
  `language`, and the Bedrock prompts instruct answers in that language
  (`SUPPORTED_LANGUAGES` in `backend/core/levels.py`).

## English-fallback content (documented gaps)

- 3D part/structure names + descriptions (scientific content nouns).
- Legal/attribution footers, deep XR modals (chat rooms, notebook,
  avatar studio, quizzes), Billing/Portal/VR/Campus-Map bodies, link-card
  description lines, loading fallbacks.
- Static Bedrock-fallback guidance (returned with `isDemoGuidance: true`).

Native-speaker review of zu/xh/af/fr/es strings is still recommended —
they were authored for clarity, not certified.

## Rules for contributors

- New UI strings go through `t('namespace.key')` — never hard-code copy in
  converted surfaces.
- New keys go into `src/i18n/locales/en.json` FIRST, then all 5 locales.
- `npm run i18n:check` enforces exact key parity (missing/extra/empty fail).
- Subject/system display names live under `subjects.*` / `systems.*` so all
  viewers share one vocabulary per language.
